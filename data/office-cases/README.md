# 可直接运行的虚构办公案例

这些材料模拟“衡川数智”的季度办公，企业名称、员工、项目、服务单和反馈均为虚构，供同一个系统中的普通工作汇报使用。它们不是独立演示空间，也不需要切换端口。旧的 `data/demo/` 小规模回归夹具原样保留。

## 如何使用

在正在运行的系统中创建工作汇报，勾选使用系统本地办公案例数据，先点“取消全部选择”清除旧材料选择，提交下面任意一段需求即可。系统按需求选择对应的数据类别，并通过原有五个业务 Agent 自动处理。先用离线模式可验证完整流程且不调用付费模型；需要展示真实模型协作时再选择真实模型模式。运行应依次看到 Manager、Planner、Data、Writer、Checker，审核通过后由 Manager 验收，得到 Markdown 和 PDF。

技术部需求可直接复制：

> 请生成2026年第二季度技术部工作汇报，使用本次授权的系统本地办公案例资料。内容包括工作概况、项目进展、人员考勤、成果与改进、问题与风险、下一季度计划。请按材料统计可识别项目、已提供排班样本工时和成果，列明统计范围与数据限制，依据工作说明中的背景编写风险和计划，不编造预算、收入、成本、同比或效率提升数据。输出规范的Markdown和PDF。

行政部需求可直接复制：

> 请生成2026年第一季度行政部服务工作汇报，使用本次授权的系统本地办公案例资料。内容包括服务工作概况、满意度反馈、问题与整改、下一阶段计划。请按同一量表统计有效反馈，明确剔除无效记录并说明样本限制，依据服务说明编写业务背景和改进计划。未提供的服务总单量、历史同期等指标不编造。输出规范的Markdown和PDF。

CSV 和 TXT 也可以在原有材料管理页手动上传；CSV 按下表选择分类并确认字段映射；TXT 选择“文字材料”，确认所属部门与起止期间。起止期间使用左闭右开区间，结束日不纳入统计。无须把本目录的脚本、README 或 manifest 当作业务材料上传。

## 数据规模与业务关系

技术案例设四个业务组、二十四名匿名员工，覆盖季度内六十五个虚构企业工作日，形成一千五百六十条人员与日期唯一的考勤记录。日常记录包含正常、请假、缺勤、迟到和超计划工时，能关联到员工负责的项目。每条都保留原始计划工时与实际工时，不用平均值补齐明细。

十二个项目各有四月、五月、六月月末快照。相同项目的生效日、负责人、业务组保持一致，进度不倒退；完成状态、完成日期和交付成果相互对应。除了完成项目，也有待验收、依赖未解除和暂停项目。四十二项成果分别为技术文档、质量改进、运维优化和项目交付，均关联存在的项目。文字记录说明项目依赖、暂停原因、验收边界和后续安排。

行政案例每月七十二条反馈，覆盖会议支持、物业报修、办公用品、差旅支持、入离职支持和档案借阅。每条保留服务单、匿名提交者、渠道和文字意见。十二条无效反馈仍保留在原始文件中，分别标注重复提交、评价场景不符、主动撤回和内部测试；评分本身合法，系统依据有效标记剔除，而非通过导入错误丢弃。

额外的业务背景列用于人工核查，数值统计仍严格使用系统支持的字段映射；风险和计划以 TXT 的可追溯文字来源为依据，不宣称 Agent 已统计了任意额外列。

考勤口径必须保留：本案例的“工作日”只是周一至周五的虚构企业排班，**没有套用法定节假日和调休**。请假不扣减计划工时分母，超计划工时不提高出勤率；实际工时较长也不能自动解释为经批准的加班。

`manifest.json` 中公布匿名人员名单和全部工作日期。只有将这两份明确名单一起传给支持该参数的统计接口，才可核验声明排班范围的覆盖率为 100%，对应出勤率约 95.3486%。普通自动运行未显式声明人员与日期时，整体覆盖率及整体出勤率应保持未知，只报告已提供样本的结果。完整的合成文件也不能证明真实部门整季度已覆盖。

项目台账没有真实企业完整主档证明，应称“可识别项目”；反馈不是全体员工抽样调查，不代表全部员工意见。月度分数变化只作描述，不据此判断整改的因果效果。未提供的成本、收入、收益、总服务单量、同比和效率提升均不能推断。

## 确定性生成与核验

```bash
python3 data/office-cases/generate.py
.venv/bin/python -m pytest tests/test_office_case_data.py -q
```

生成脚本只使用 Python 标准库。固定种子为 `office-cases-2026-v1`，事件来自 `SHA-256(seed|事件类别|稳定业务编号)` 的指定字节取模；不存在依赖 Python `random()` 版本的随机序列、不读取当前时间、不联网、不调用大模型。项目快照、成果和背景文字是脚本中的固定业务清单。

默认重建本目录下的六份业务材料和 `manifest.json`；可用 `--output /其他目录` 在临时目录生成同一份数据。manifest 记录每份材料的 SHA-256、字节数、部门、期间、排班声明和精确汇总。测试通过现有材料导入与字段校验、统计函数独立核对固定值，并核查完整日期分布、项目进度、交付日期、人员与项目关系、无效反馈和声明范围边界，不需要 API 密钥。
