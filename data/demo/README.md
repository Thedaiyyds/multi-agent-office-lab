# 独立演示材料

这些文件是公开虚构数据，不含真实员工、客户、账户或业务资料。它们是材料导入源文件，不是系统实际运行截图，也不是已生成的报告。系统不会在正常空间自动加载。

- `technical-q2/`：技术部2026年第二季度示例。CSV分别表示项目、考勤、成果；TXT与DOCX表示文字补充材料。
- `administration-q1/`：行政部2026年第一季度满意度示例，可手动导入CSV、TXT、DOCX。
- `build_docx.py`：重建上述两份DOCX源材料的脚本，需要`python-docx`。该脚本不调用模型、网络或产品接口。

目录中仅放供导入的材料，说明与脚本保留在上层，避免把说明误当业务数据。重复运行脚本只会覆盖这两份模拟DOCX，不会读取或修改正常工作台数据。

## 独立手算参考（供后续alpha.3核对）

**alpha.2仅解析、预览和确认材料，不提供下面这些汇总统计。以下是案例设计时的手算，不是本版运行结果。**

技术部：`项目进度.csv`有5条快照、4个不同项目。DEMO-P01早期记录必须被期末前最新快照替代；`progress`统一采用0—100的百分数（100表示完成）。期末为2个completed、2个in_progress，完成项目占比2/4=50%。3条成果均在季度内，其中2条项目交付、1条流程改进。

考勤：只有2位虚构人员、2个模拟排班日，4个人日。计划小时8+8+8+8=32；有效实际小时8+4+8+8=28；请假4小时。若后续采用说明书约定的“实际小时截断至当日计划小时、请假不自动扣减分母”口径，则样本有效工时占比28/32=87.5%。这不是全季度出勤率，也不代表真实人员绩效。覆盖仅在已给出的4个人日范围内为4/4。

行政部：4个有效反馈，量表均为1—5，分值4、5、3、4；均分(4+5+3+4)/4=4.0，样本数4。不计算跨量表归一、不推断往期变化或总体满意率。

## 隔离方式

按[演示指南](../../docs/demo-v2.0-alpha.2.md)启动专用8530端口及`outputs/demo/workbench.sqlite3`，再在帮助页面进入演示空间并显式加载案例。正常开发仍使用8520端口与`outputs/workbench/workbench.sqlite3`。

本地简单数据接口只提供这些公开模拟记录，不接受外部URL，在正常空间返回403。演示不会触发模型调用，也不会改动源代码、环境密钥或正常空间材料。重复加载复用已确认版本，但解析产生的导入草稿及暂存原件仍留在outputs/demo内。
