# v0.5 协作开发与独立审查记录

本文记录已执行的协作开发、离线审查及已有真实产物的只读复核。发布提交和远端 CI 验证以 [validation-v0.5.md](validation-v0.5.md) 的实际记录为准。

## 实际分工

开发者是一位人类。下列 A/B/C 是主协调实际分派的三个 AI Agent，不是三位人类成员或伪造的 Git 作者。

| 负责者 | 已完成范围 | 实际交叉审查 |
| --- | --- | --- |
| 主协调 | 共享契约、动态 HTTP 模拟、CLI、独立端到端用例与集成；负责后续实测、证据和发布 | 汇总模块接口、预算、失败出口与文档 |
| AI A：流程与导出 | 真实 LangGraph 有界条件循环、故障注入、逐轮历史、最终报告导出门禁与相应测试 | 审 B 的正文约束、程序审核优先与 Writer 反馈；增加任意正文无法导出成功报告的回归 |
| AI B：报告与审核 | 受约束正文、真实上一草稿和 Review 输入、程序错误优先、事实校验及相应测试 | 独立审 C 的重试、预算、错误类型和事件；运行相关 60 项测试通过 |
| AI C：运行时与最终独立复核 | 安全错误分类、可选网络重试、实际 HTTP 尝试预算、脱敏日志和相关测试；本审查及架构文档 | 审 A 的循环、历史和导出；复现并复核修复一次导出审计漏洞，运行完整集成测试 |

各 Agent 独占文件开发，主协调集成共享契约；本轮没有虚构三人提交或人类审核身份。

## 审查发现与闭环

| 问题或边界 | 处理与实际证据 |
| --- | --- |
| 无依据正文可能被模型判为通过 | 完整工作流要求章节正文逐字等于 `allowed_section_texts`；错误数字、汉字数量、整体按计划推进和资源紧张等正文被程序拒绝。`test_grounded_reports.py`、`test_writer_revision.py` 以及 `test_workflow_export.py` 覆盖，即使模型通过且同步节点记录也不生成最终报告 |
| 首轮错误后的“修复”不能只是预设成功状态 | `test_revision_graph.py`、`test_v05_integration.py` 在 HTTP 层核对第二次 Writer 的实际输入包含首轮草稿与 Review；四项 metrics 和来源不变，Writer 新输出经 Checker 复审 |
| 持续错误或失败节点不能被当作成功 | 修改上限 0/1/2 均精确终止；`needs_input` 不进入返工；返工 Writer、Checker 或预算失败保存已有节点、草稿和审核，未完成的轮次不伪造 Review |
| [P2] Checker 的模型请求事件全标失败，导出仍可能被判为可通过 | C 在正常 mock 结果上独立复现；A 修复导出门禁，要求最后 Checker 模型请求成功，并复算 HTTP 次数、逻辑次数、每次输出预留与重试事件。C 再次复核：正常结果允许，篡改后拒绝。`test_final_export_rechecks_actual_model_attempt_accounting` 含 7 类回归 |
| 可选重试可能绕过共享额度 | Session 每次 HTTP 尝试重新准入，Adapter 在 Session 中强制零内部重试；每个逻辑请求最多重试一次，全局最多两次。`test_retry_runtime.py` 覆盖默认关闭、0/1/2 全局额度、超时/连接/429/5xx、鉴权、结构与预算边界 |
| 睡眠或参数失败也被错误计作一次重试 | 参数在请求前检查；等待失败时不增加 HTTP/retry 计数及输出预留。相关测试核对计数、无额外请求及安全错误文本 |
| 失败请求没有 usage，不能编造零消耗 | Adapter 对每个实际尝试保存 usage 的白名单值；任何尝试缺某字段，该累计字段为 `null`。不保存 provider 错误正文、配置密钥或推理内容 |

已发现的阻断导出问题已闭环。该门禁检查记录一致性，不提供密码学签名或抵抗有意同步伪造整份本地记录的能力。

## 真实 API 准备检查与限制

- `run` 默认 mock；真实运行需显式 `--mode live`。故障实验独立为 `workflow-test --case ...`，原 Writer 输出与注入后输出分开保存，不把注入错误冒充模型自然犯错。
- CLI 可下调 `--max-requests`、`--max-output-tokens`、`--max-revisions`、`--timeout-seconds`；默认 `--retry-budget 0`，DeepSeek profile 禁用 thinking，内部不自动重复整轮验收。
- 正常完整链路最多 6 个逻辑调用，允许两次返工最多 10 个；全局重试硬上限 2，总 HTTP 硬上限 12，总输出预留硬上限 5568。输入 token 另计，字符数限制不等价于输入 token 限额。
- `revision_count` 表示已开始的返工尝试：Checker 路由到下一 Writer 时增加；即使该 Writer 失败也计数。初稿不计入返工。`logical_request_count` 表示通过本地参数检查的模型调用意图，预算拒绝可能没有对应 HTTP；正常完成时等于首尝试 HTTP 数。
- constrained 正文只描述已支持事实的范围，四项核心统计通过结构化事实渲染。建议标明“尚未实施、待人工评估”，其可行性仍需人工判断；没有实现通用自然语言事实验证。
- 问题材料仍是未筛选材料，不能归因于当前部门或日期；不据此推断具体风险。mock Manager 是受支持输入的脚本解析，不代表真实模型自然语言理解能力。
- 此次独立复核没有新增真实 API 调用，也不包含 GitHub 远端 CI、merge/tag、运行截图或最终课程实验报告。远端验证和截图只能由实际结果补充；文本日志和 Mermaid 图不替代运行截图。
