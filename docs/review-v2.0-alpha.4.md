# v2.0-alpha.4 独立验收记录

状态：独立接口与执行验收通过，未发现剩余阻断；浏览器、全仓回归和发布检查由主协调者另行验收。该结论不代表整个实验系统完成。

## 依据与范围

依据实验指导书2.3、5.3.3、5.4.3及实施说明书R2，核对正常工作台的一段自然语言需求、普通授权材料，以及Manager→Planner→Data→Writer→Checker→Manager验收的实际依赖。默认完整输入不要求人工确认大纲或批准才能继续。

本版重点是五角色编排及真实状态，不把alpha.3已完成的统计、旧版链路或离线模型回复作为新版真实模型验收。Markdown/PDF正式交付仍按alpha.5退出条件验收。

## 必须验证的行为

- 技术部Q2与行政部Q1通过正常材料上传和正常运行接口提交；不切换端口、工作空间，不改样例原件。
- Planner的数据需求实际决定Data选择哪些工具；Data基于全量授权记录计算，Writer只消费冻结事实与授权文字。
- Writer事实引用必须指向本次数据；数值、单位、章节与Markdown的程序错误不能被模型的“通过”覆盖。
- Checker反馈驱动有限返工，超过两次仍不合格则失败；Manager最后验收，不能仅有开头需求解析。
- 幂等键、期望版本和空间校验阻止重复或越权运行；取消后不能被迟到模型结果改成完成。
- 模型请求前持久化预算预留；缺usage不伪造零，重启中断不自动重发可能已经收费的请求。
- 缺材料、缺需求、统计冲突、预算不足与供应商异常保持可解释非成功状态。

测试仅使用临时SQLite、公开合成材料及本地脚本模型响应，不读取.env，不向真实供应商发送请求。

独立测试文件`tests/test_workbench_execution_acceptance.py`实际执行30项通过，Ruff检查与格式化通过。测试启动真实FastAPI、SQLite单worker及LangGraph，文件经公开上传/确认接口入库，再通过正常`/runs`提交。

## 审查发现与关闭

- 发现多行段落内`# 标题`可绕过仅匹配字符串开头的检查；已按多行模式校验并保留独立回归。
- 交叉审查发现Planner误读自身未完成节点而丢失Manager输出；已改为读取已完成Manager结果，独立测试直接检查模型请求中的拆解任务。
- 交叉审查发现不持执行锁的第二实例关闭可能影响主实例；已加所有权约束，并以两个同时启动的应用实例验证。
- 考勤完整季度与样本范围保持区分，未通过降低断言把缺数据当零或冒充完整覆盖。

开发期初轮测试还发现验收脚本自身把来源SHA中的“99”误当错误业务文本，以及使用了错误草稿更新URL；脚本已分别改为检查完整错误断言句、调用现有`PATCH /reports/{id}/draft`，没有降低产品业务断言。

## 结论与限制

本版五角色编排和受控离线端到端链路具备继续发布验收的条件。测试中的live模式仅表示走真实HTTP适配器，HTTP被MockTransport本地拦截，不是实际大模型生成证据。真实模型验收由主协调者另行限预算执行；不得用此30项离线结果替代最终模型集成、正式Markdown/PDF下载、安装复现或完整实验报告。
