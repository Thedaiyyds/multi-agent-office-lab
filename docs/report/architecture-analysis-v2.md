# 多智能体办公协作系统体系结构分析

本分析对应正常8520工作台的React、FastAPI、LangGraph和SQLite实现。五个Agent是集中编排的业务角色，共用受控模型适配器；它们不是五台服务器，也不等同于人类开发组员。

## 一 组件职责与依赖

| 层次 | 实际组件 | 职责与依赖方向 |
|---|---|---|
| 页面 | App、Materials、Cooperation、Statistics、Delivery、Archive | 通过同源API提交需求和材料；只读轮询，不在浏览器保存模型密钥 |
| API | workbench/api.py及路由 | 本机访问、工作区、输入契约、幂等和乐观版本校验 |
| 编排 | workbench/execution.py | Manager→Planner→Data→Writer→Checker→Manager，共享冻结状态与预算 |
| 数据 | materials.py、statistics.py | 三格式全量解析、版本冻结、确定性统计、来源与限制 |
| 文档 | delivery.py、pdf_export.py | 合格快照、不可变修订、两角色复审、MD/PDF及哈希门禁 |
| 存储 | SQLite和受控文件目录 | 需求、执行、事件、材料与报告文件在本机持久化 |

模型输出先通过Pydantic结构校验，再经过业务校验。候选结构可以留作诊断，但不能绕过部门、半开日期和报告版本约束。Data使用Planner实际要求的数据类别读取授权版本；统计工具产生事实编号，Writer只能引用这些事实或授权文字。Checker结合程序核验与模型语义检查，Manager最终检查当前需求和审核结果。

## 二 状态与通信

每次角色调用将实际上游输入、结构化输出、事件与预算写入执行记录。LangGraph条件边根据缺失、审核和终态路由；Checker不通过可返回Writer，初稿后最多两次修正。保存的新正文作为独立修订，事实与来源冻结，后续仅执行Checker和Manager，不能静默重写用户编辑。

队列使用单worker与进程文件锁，SQLite短事务只处理状态及预算，不把数据库事务包在模型网络等待中。幂等键同内容返回原任务，不同内容冲突；需求版本、工作区与取消状态在最终验收时再次核对。Unix进程锁的取舍适合本机课程规模，原生Windows未验证，应使用WSL2。

## 三 统计可信性

模型负责语言理解和撰写，程序负责数值与交付权限。项目取结束日前最新有效快照；考勤区分样本、明确排班范围和完整季度；成果按ID去重；满意度按相同量表分别计算。缺失与零不能混同，冲突不按上传顺序覆盖。来源同时记录原始材料、版本、SHA256、字段和行或段落定位。

这一约束能防止模型改写已建模指标，不能证明全部自然语言都正确。最终行政稿出现样本用词不准确，人工修订后由两角色复审，验证了必要的语义复核与修订机制。模型通过不能覆盖程序错误，程序通过也不能当成所有业务陈述绝对真实。

## 四 失败与成本

请求前先持久预留请求数与输出上限，自动网络重试为零，供应商usage缺失保持null。模型错误只保存允许的安全代码，不把供应商原始异常或密钥送往页面。取消阻止后续节点和迟到成功发布；在途供应商费用未必能撤销。重启将未知在途执行标为中断，不自动重发付费请求。

合格内容与文件生成分别处理。导出失败保留合格快照和失败状态，可离线重试；Markdown与PDF均从同一冻结Markdown产生。中文字体随源码分发并嵌入PDF子集，不需要Office或系统字体。下载再次核验快照哈希、绑定该哈希的Checker/Manager凭据、受控路径和文件SHA，旧合格版可保留下载但明确非当前。

## 五 质量证据与适用范围

确定性统计有手算与边界测试；执行和交付有独立临时数据库及本地HTTP夹具；PDF实际解析字体与正文并进行逐页视觉检查；正常界面实际操作另行记录。两个普通场景使用真实DeepSeek V4 Pro完成六节点和双格式文件，成功与失败的用量分开保留。源码副本在没有.env和业务数据的环境中复现安装、构建、真实本地PDF、重启下载和两角色复审。

系统面向本机课程实验，采用集中式架构降低部署与跨服务一致性成本。未来若扩展至多人生产环境，应在真实需求出现时补充身份权限、并发任务、业务接口和更严格的语义评估；当前不将这些未实现能力包装为已完成。
