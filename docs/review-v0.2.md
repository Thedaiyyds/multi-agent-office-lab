## 发现与修复

1. C 发现 CLI 默认数据来源判定在受控处理外执行路径解析，循环符号链接可能产生 traceback。协调者处理解析异常，由读取模块返回安全错误；独立 CLI 测试覆盖该路径。
2. A 和 B 发现共享模型的统一去空白设置会修改 CSV 原值与 issues.txt 首尾空白。协调者为 RawRow.values 和 IssueMaterial.text 单独保留原文本；C/B 的真实文件保真测试通过。
3. A 发现 Python CSV 默认单字段上限低于计划中的文件上限，合法长描述可能被拒绝。A 临时将字段上限调整到 2 MiB，并在 finally 恢复原限制；独立测试覆盖长字段及恢复行为。
4. A/B 统一 issues.txt 的 record_count 为 0，避免把自然行数当作业务问题条数；原材料标注 scope=unfiltered，完整说明其归属没有经过筛选。

以上发现均在合并前处理。指标使用全量数据校验结果，实际集成测试确认：其他部门或日期范围外的非法记录同样阻止全部指标输出；不能把筛选作为忽略错误的办法。

最终测试数量、运行证据和新克隆复现结果以 [验证记录](validation-v0.2.md) 为准。当前能力只包含确定性数据工具，尚无业务 Data Agent 或模型生成报告。
