# 基于材料规划汇报

## 操作步骤

1. 打开正常工作台的“材料库”。勾选需要使用的文件，例如技术部的项目进度、人员考勤、成果统计和工作说明，点击“规划汇报”。也可以不勾选，进入规划页面后选择。
2. 检查所选文件，按需填写“汇报要求（可选）”。可以留空，让团队根据材料提出方案；跨部门或期间也能直接规划：默认提出综合汇编，并提供按部门分别汇报的方向。如果只想突出某一范围，可以写明，例如“规划技术部2026年第二季度汇报，重点关注交付风险”。
3. 选择真实模型或明确选择离线模拟，点击“生成汇报方案”。真实模式会产生Manager与Planner的模型调用，受到同一任务预算限制。
4. 查看建议标题、覆盖部门、期间、汇报重点和大纲。材料涉及多个范围时，可切换“汇报方向”，选择综合汇编或其中一个单独方向。每个章节显示材料依据，页面列出材料缺口和统计限制。可修改标题、重点、期间、章节要点及数据分类，也可增删和调整章节顺序。
5. 点击“确认方案并生成”，系统保留同一任务，直接从Data阶段继续。确认后的标题、范围和大纲用于实际报告，不重新调用Manager与Planner改写方案。
6. Checker审核与Manager验收完成后，可查看报告并下载Markdown/PDF。点击“暂不生成”则结束本次方案，不创建报告。

只选择文字材料时，可以规划文字汇报，不生成量化指标。没有文字说明又取消全部统计分类时不能确认；无材料依据的章节、超出文件支持范围的部门/日期会被阻止。

## 与实验流程的关系

本功能是可选的用户确认步骤，属于产品交互扩展，不声称实验指导书要求人工审批。原来的“一段需求→全流程生成”入口仍可直接使用。

规划阶段：Manager读取经过校验的文件概况（类型、行数、部门与期间）明确需求和拆解任务，Planner按材料能力规划章节与数据需求。程序的文件概况不计算业务指标，文件行数不能当成项目数。

确认后：Data按确认范围直接读取所选原文件并计算指标、整理文字来源；Writer按确认大纲撰写；Checker检查并有界返工；Manager最终验收。五个角色的职责保持明确。

同一任务记录完整节点与用户确认事件。方案等待期间不会自动推进，刷新和重启服务后仍需用户确认。重复确认不会创建第二份报告，规划与生成共用原来的请求和输出预算，调用用量跨阶段累计。

## 数据边界

文件内容继续保存在工作目录，不缓存材料明细进数据库。规划概况、用户确认内容、运行记录与报告结果保存以便恢复和追溯。方案绑定选定的文件ID和校验值；新增其他材料不自动替换本方案文件。所选原文件缺失或被修改时，确认会报错，不能使用旧内容兜底。

综合汇编默认各部门整期独立计算；用户要求或Planner提出分段时，按确认的分段分别计算。指标、文字引用和来源保留范围标识；不同期间的项目数、出勤率、满意度不能混算为一个总量或平均值。选择单独方向时，不夹带其他方向的数据。页面起止日期均包含当天，API内部仍用半开区间避免边界重复。模型提出分段时会在确认页列出，可选择改为整个期间汇总。CSV读取每个部门的实际最早和最晚记录日期，不预先分季度。留空要求时，Manager可依据材料提出合理期间，Planner可选整期汇总、周、月、季度或自定义分段，不能把文件日期自动补齐到季度末；用户明确要求季度时保留该目标期间，同时单列实际材料覆盖。TXT/DOCX文字按已确认部门和期间使用。预算等未提供的数据不作事实结论；人员名单和应出勤日历不足时，考勤仅代表样本。
