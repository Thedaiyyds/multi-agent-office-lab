日期：2026-10-16。依据：`docs/proposals/v2.0-review/development-spec.md` 第 12—15 节。

## 2. 自动检查与人工检查分工

后端开发者负责 API 单元测试：临时 SQLite、重启重连、空间隔离、输入校验和乐观锁。测试不能共享用户数据目录，不能调用付费模型。独立审查者复核测试能捕获数据污染和覆盖风险，并独立执行可用检查。

前端自动门槛为 TypeScript 检查与生产构建；实际页面另在浏览器验证 A01、A02、A05、A09、A10、A11，截图必须来自本版运行结果。仅通过构建不代表 UI 验收完成；仅检查 CSS 源码不代表已验证移动端。

现有 CI 基线包含 `uv sync --locked --python 3.12`、Ruff、完整 Pytest、graph-demo、data-check、agent-demo mock、run mock、workflow-test mock 与离线 acceptance。新版需要额外覆盖前端锁定安装及构建。实际执行命令以发布分支的 CI 与包脚本为准。

## 3. 发布门槛

1. 验收结果写明已通过、失败和未执行，记录真实数量及证据位置。
2. 需求与实现一致：阶段未实现的材料、智能体与导出不可点击后冒充成功；保留后续阶段说明。
3. 独立审查无阻断问题；PR 描述说明当前能力与限制；CI 通过后按版本流程合并、标记。
4. 主要界面提交用户查看；用户认可主要界面是进入 alpha.2 的产品门槛，不能由测试数量替代。
