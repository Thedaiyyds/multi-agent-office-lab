# v2.3.0：基于材料规划汇报

材料库增加文件勾选与“规划汇报”入口。Manager和Planner先提出一份可编辑方案，展示主题、范围、章节、文件依据和缺口。只有用户确认后才创建报告并继续Data、Writer、Checker和Manager验收；不确认则不撰写正文。

复用现有LangGraph与持久化运行记录，新增`awaiting_confirmation`状态和有防重复提交的确认接口，不新建Agent或方案管理系统。确认后从Data开始，沿用用户调整的需求与大纲，不重复调用前两个角色。规划和生成共用预算，用量跨阶段累加。待确认方案可跨服务重启恢复，也可以取消。

保留文件直接读取、正常8520端口、原来的直接生成入口和Markdown/PDF交付。仅文字材料可生成文字汇报，不产生虚构量化指标；跨部门/期间歧义、缺少章节依据、文件变化时明确提示。

验证包含普通与大型材料、暂停门禁、用户修改落地、并发重复确认、空间隔离、文件缺失/变化、取消、服务重启、两段预算及实际双格式导出；模型采用离线或本地脚本传输，不请求付费服务。详见本版验证摘要和操作说明。

本地结果：874项Python测试、13项前端API测试、Ruff检查、TypeScript/Vite构建通过。实际浏览器走通材料勾选带入、离线方案暂停、修改标题与章节、离开保护、确认后完整生成、双格式下载和暂不生成；手机390px宽度无横向溢出。所有UI测试使用临时数据库，正常工作空间的8份报告、14份材料、10次运行和30个既有文件内容未变化。
