# v2.5.0：由需求和模型决定汇报期间

此前材料规划把CSV记录日期映射到季度，Manager必须复制默认范围。同部门跨季度文件被拆开，全部材料默认形成十个季度范围，第四季度的结束边界显示为2027-01-01，即使记录只到10月21日。正文又逐条重复范围、指标名和事实编号，影响阅读。

现在文件扫描仅提供每个部门的实际记录范围，TXT/DOCX使用导入时确认的覆盖范围，不预设季度。Manager结合用户要求选择主题与起止期间，留空时可在材料范围内提出阶段或其他合理汇报；Planner通过可选periods提出周、月、季度或自定义分段，不需要比较时整期汇总。Data执行确认后的真实范围及分段，各部门独立统计，避免把同一项目的不同时间快照重复相加。分段越界或重叠会在确认前拒绝，不能制造重复指标。用户明确要求季度时仍支持季度目标，同时列明实际材料覆盖；页面将内部不含结束日的区间转换为包含首尾的日历日期。

确认页展示模型建议的分段，用户可改为整期汇总。五角色职责与原流程保持：Manager需求接收与拆解→Planner内容规划→Data文件读取、确定性统计与结构化结果→Writer撰写→Checker审核和必要返工→Manager最终验收。确认后接续同一运行，无额外模型请求。规划角色输出上限从384调整到768以容纳可选分段，任务总预算5568保持不变。

Writer新增受授权事实约束的value引用，仅展开数值和单位；fact引用展开简短指标名，不在新正文重复事实编号、范围及哈希。数据值保持原始精度，显示最多两位小数；完整定义和来源仍在核对附录。网页默认收起统计、限制与来源，展开来源后选择需要追溯的指标，避免首次渲染全部逐行来源。文字片段沿用5000字总预算，按文件轮流取样，避免靠后的部门完全没有文字背景；截短和未选片段仍明确披露，所有结构化记录继续全量统计。

渲染样式标记保存在统计快照内；旧归档仍使用原始渲染规则，内容哈希及已导出的文件不重写。新期间逻辑适用于新建规划；已确认范围不会在后台被偷偷修改。用户可重新规划现有材料获得新报告，不自动重新发起付费任务。

验证覆盖实际日期、不补齐季度、模型自主选择周范围、模型选择自定义分段、明确季度需求、季度分段和整期汇总两种路径、分段越界/重叠拒绝、value引用校验、显示精度与旧格式兼容。全部48份材料分别通过离线模式和本地脚本HTTP模型传输跑通五角色六节点，默认四个部门范围，材料终点为2026-10-21，完整指标、来源及Markdown/PDF交付保留。所有模型验证使用本地夹具，不调用DeepSeek。浏览器检查在临时数据上完成，不向用户工作区写入测试记录。
