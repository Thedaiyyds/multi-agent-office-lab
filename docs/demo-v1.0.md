# v1.0 现场演示脚本

使用 [安装说明](deployment-v1.0.md) 启动工作台，选择“离线模拟”和“实验样例”。以下数据均为课程模拟材料，本地 HTTP 夹具用于验证协议及控制流，不冒充模型自然生成证据。页面能显示真实节点、数据来源和审核；mock 执行很快，可能直接看到终态，顺序仍可从节点日志检查。

## 场景一：研发部第二季度报告

需求填写：

> 生成研发部2026年第二季度工作报告。日期范围为2026-04-01（含）至2026-07-01（不含）；章节依次为工作概况、主要成果、问题与风险、后续计划。

提交后查看五角色：需求经理、规划助手、数据助手、撰写助手、审核助手。核对项目数 3、完成项目数 2、完成率约 66.7%、成果数 2；正常状态为 completed，未开始业务返工。2/3 是项目完成率，不是系统开发完成度。项目按范围内每个 project_id 的最新快照去重统计；7 月 1 日样例不属于 Q2。

展开数据来源，核对文件 SHA 和行引用；查看最终审核通过后下载的 `report.md`，文件名附带 run UUID。下载属于读取已导出结果，不重新调用模型。若需要展示命令行同图运行：

```bash
uv run --locked office-agents run --mode mock --request '生成研发部2026年第二季度工作报告' --output-dir outputs/demo
```

## 场景二：市场部第二季度报告

研发场景结束后点击“新建任务”，仍选样例与离线模拟，需求改为：

> 生成市场部2026年第二季度工作报告。日期范围为2026-04-01（含）至2026-07-01（不含）；章节依次为工作概况、主要成果、问题与风险、后续计划。

核对项目数 1、完成项目数 0、完成率 0%、成果数 1；报告部门应为市场部，不是复用前次研发结果。正常状态为 completed、业务返工 0，每次运行有独立 UUID 与产物目录。`issues.txt` 为未按部门/日期筛选的原始材料，不参与这些指标统计；可以在报告查看其来源边界说明。

```bash
uv run --locked office-agents run --mode mock --request '生成市场部2026年第二季度工作报告' --output-dir outputs/demo
```

## 故障实验：初轮错误被审核并返工

新建任务，使用研发 Q2 需求。在故障实验开关中选择“错误事实”，保留最多两次业务返工、零网络重试。该选择会**主动注入**初轮项目数错误，属于故障实验，不能称为模型自然失误。

查看初轮审核 `fact_value` 意见，确认错误值 4 被拒绝；返工轮以原指标 3 修复，通过后才出现最终报告下载。逐轮目录保留错误草稿、审核意见与修正稿，业务返工次数为 1。命令行等价演示：

```bash
uv run --locked office-agents workflow-test --case bad-fact --mode mock --request '生成研发部2026年第二季度工作报告' --output-dir outputs/demo
```

再新建任务选择“持续错误”，最多两次返工。预期最终 `review_failed`，不能下载最终报告，但可以查每轮失败意见。该 CLI 命令按业务失败返回 1，这是预期的拒绝结果：

```bash
uv run --locked office-agents workflow-test --case always-bad --mode mock --request '生成研发部2026年第二季度工作报告' --output-dir outputs/demo
```

## 上传：数据改动确实进入统计

在本地复制样例，不修改仓库原文件：

```bash
mkdir -p uploads/demo
cp data/samples/projects.csv data/samples/achievements.csv data/samples/issues.txt uploads/demo/
```

用 CSV 编辑器在副本 `uploads/demo/projects.csv` 找到 P003 的 `2026-06-30` 行，将 `status` 从 `active` 改为 `completed`，将 `progress` 从 `75` 改为 `100`，保存 UTF-8。新建任务选“上传我的文件”，同时上传三个副本；等三个文件均出现在列表后提交研发 Q2 需求。

核对项目数仍为 3，完成项目数变为 3，完成率变为 100%，成果数仍为 2；来源为用户提供数据，projects.csv 的 SHA 与样例不同。此步骤证明程序按本次上传字节统计，而非硬编码页面指标。

另建一个副本，将 projects.csv 的必需字段 `project_id` 改成 `project_code`。新建任务上传这三个文件，预期在任务接纳前出现校验错误，没有工作流 UUID、模型请求或最终报告。测试后不要把自有上传文件加入 Git。
