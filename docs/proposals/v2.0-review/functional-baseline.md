## 保留的实现安排

继续使用现有React、FastAPI、LangGraph、SQLite和已经完成的alpha.1界面、草稿持久化、正常/演示空间隔离。保留原版本顺序及每版PR、审查、CI、merge、tag流程。此前核查记录提出的版本重排不采用。

教师补充允许任意开源框架，因此不因指导书的场景名称改换OpenClaw。指导书的安装命令不作为本项目必须执行的命令。

## 功能与文件格式

| 项目 | 实施和验收依据 |
| --- | --- |
| 需求接收 | WebUI接收自然语言工作汇报需求；Manager解析主题、部门、期间、重点和输出要求，产生任务拆解结果 |
| 内容规划 | Planner接收Manager任务，生成包含章节要点、内容安排和数据维度的大纲，并可按需求调整 |
| 文件读取 | 支持.txt、.csv、.docx三种本地材料；文件分类、预览和校验服务于Data工具调用 |
| 数据接口 | 支持简单本地数据接口，模拟企业数据系统；数据来源明确，模拟数据不冒充真实数据 |
| 数据整理 | Data接收Planner的数据需求，读取授权文件/接口，整理项目进度、人员考勤、成果统计，并校验异常数据；行政场景支持服务满意度 |
| 撰写 | Writer同时消费大纲和整理后的数据，生成完整工作汇报，规范Markdown标题、段落和表格 |
| 审核 | Checker检查完整性、数据准确性、格式规范，输出详细问题，支持简单自动修正或反馈Writer修订 |
| 通信与调度 | 实现Manager→Planner→Data→Writer→Checker的消息与结果传递；Checker结果返回Manager验收。具备Agent未响应等异常的有界恢复或重新调度 |
| 报告输出 | 支持.md与.pdf。技术部测试场景应实际导出PDF，行政部场景应实际生成Markdown；两种输出均来自本次审核合格内容 |
| 系统集成 | 统一应用入口和编排服务，启动后业务角色可用，通过WebUI任务触发完整协作；不要求使用OpenClaw特定网关 |

DOCX是指导书规定的输入材料格式，不代表业务报告必须导出Word。Word导出从必做验收项降为可选增强，不影响Markdown/PDF必需交付。旧版JSON运行记录仍可用于内部证据，不能替代业务报告。

## 主流程与既有页面的关系

保留现有首页、任务页、材料页和草稿表单。在已有页面中补齐自然语言任务入口及五角色执行能力，草稿字段和章节编辑可作为辅助，不重新设计整套页面。

材料与配置齐备时，任务按Manager拆解→Planner规划→Data整理→Writer撰写→Checker审核修正→Manager验收→输出报告执行。五个角色中Manager负责起始调度和最终验收，末尾回到Manager不意味着增加第六个Agent。

大纲确认、人工编辑、批准和归档可保留为辅助功能，但不强制阻断默认自动协作演示。缺必要信息、数据异常、预算耗尽或修正失败时，应显示实际问题并暂停或失败，不能生成虚构的合格结果。

## 两个必须对齐的测试场景

1. 技术部2026年第二季度工作汇报：包含项目进度、人员考勤、成果统计；正文采用Markdown，能够导出PDF。
2. 行政部2026年第一季度工作汇报：突出行政服务满意度，生成Markdown报告。

案例作为普通样例文件保留，正常首页不预填。用户在正常工作台上传/选择材料并输入需求即可演示，无需切换演示空间或启动额外服务。验收要展示输入、五角色实际协作、数据来源、审核及最终Markdown/PDF文件，纯材料导入不算完整案例跑通。新版本最终验收需要真实模型证据，离线模拟结果单独标明。

## 版本顺序保持

| 版本 | 保留的阶段重点 |
| --- | --- |
| alpha.1 | 已完成UI、需求草稿和持久化基础 |
| alpha.2 | 材料接入，补齐TXT/CSV/DOCX和简单本地接口，预览与校验 |
| alpha.3 | 项目、考勤、成果、满意度统计及来源验证 |
| alpha.4 | 五角色完整编排、任务调度、结果回传、异常处理和自动修正链路 |
| alpha.5 | 报告审核完善、编辑及Markdown/PDF交付；Word不列为必做门槛 |
| alpha.6与正式版 | 两场景端到端、稳定性、安装复现、实际截图和实验报告 |

本表保留原阶段边界，并不把每一阶段视为完整实验系统。最终必须以功能闭环和实际输出文件验收。
