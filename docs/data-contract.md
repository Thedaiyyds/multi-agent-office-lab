# v0.2 数据契约草案

本文是待开发接口草案，不表示 v0.1 已实现数据工具或 Data Agent。数据均为模拟办公数据，后续实现前由角色 A、B、C 共同确认。

## 文件与字段

CSV 使用 UTF-8 编码、表头和 ISO 日期 `YYYY-MM-DD`，字段名使用英文。

| 文件 | 必需字段 | 约束 |
| --- | --- | --- |
| projects.csv | project_id, department, snapshot_date, status, progress | 编号和部门非空；状态为 planned/active/completed/blocked；进度为 0–100；completed 对应 100 |
| achievements.csv | achievement_id, department, date, type, description | 编号非空且唯一；成果类型和描述非空 |
| issues.txt | 模拟问题记录文本 | 暂以整个文件作为有来源的非结构化材料，不统计问题条数 |

同一项目的部门暂定固定；同一 `project_id + snapshot_date` 的完全相同记录可去重并记录提示，内容冲突则报错。禁止任意取一条冲突记录。

## 需求输入

结构化需求包含 `department`、`start_date`、`end_date`、`source_ids`、`requested_metrics`。日期采用开始包含、结束不包含，例如 2026 年第二季度是 `[2026-04-01, 2026-07-01)`。部门精确匹配；日期非法或区间倒置返回校验错误。

## 项目统计口径

1. 按部门和日期区间筛选项目快照。
2. 对每个项目选择区间内最新快照。
3. 项目数为所选唯一项目数量；完成数为所选快照状态为 completed 的项目数量。
4. 完成率为完成数除以项目数，保留原始数值，仅在展示时按约定取整。

此口径统计“季度内有快照的项目”，不是季度末全部存量项目，也不是季度内新完成项目。一个项目跨季度出现可在各季度分别计数。项目数为零时完成率为 null，并给出原因，不能填成 0%。成果按日期和部门筛选，再按唯一成果编号计数。

## 工具结果

建议结果包含 `metrics`、`metric_definitions`、`sources`、`data_issues`、`status`。每个指标包含名称、值、单位、定义和来源引用。来源保留文件标识、内容摘要哈希和行号；当前上传路径不作为稳定来源标识。

异常需说明字段、行号和处理结果；非法必需字段阻止统计，避免静默丢弃记录。Writer/Checker 只读取指标，不能修改统计事实以通过审核。原始数据缺失应标注缺失，不让模型补造。

## 后续验收样例

- 准备 3 个项目、其中 1 个含多条快照，混入其他部门和季度。预期项目数 3、完成数 2、完成率 2/3，并能追溯选取记录。
- 检查缺字段、冲突快照、非法进度和无匹配数据；前三类返回明确错误，无匹配数据返回空指标及原因。

上述验收属于 v0.2 计划；v0.1 的模型接入测试使用 HTTP mock，不构成数据工具验收或真实模型兼容性证据。
