# v1.0 课程提交清单

本清单用于准备课程交付，不表示已经向课程平台提交，也不代替教师验收。老师补充允许任意开源框架，但仍要求三人一组，以及包含搭建过程和运行截图的实验报告。本项目采用 LangGraph；实际是一人开发、三个 AI Agent 辅助，不能把 AI A/B/C 填成三个人类组员。

## 可交付材料

| 材料 | 位置与核对方式 |
| --- | --- |
| 源码、锁文件与样例 | GitHub 仓库；正式发布后检出 v1.0.0，与实际 PR/标签 SHA 对照 |
| 实验报告 Markdown | [experiment-report.md](report/experiment-report.md)，说明搭建、五角色协作、运行与问题解决 |
| 可编辑实验报告 Word | `docs/report/experiment-report.docx`，用 Word 打开，填写身份栏并检查截图与分页 |
| 架构分析 | [architecture-analysis.md](report/architecture-analysis.md)，与实际源码核对 |
| 实际截图与索引 | [evidence/v1.0](../evidence/v1.0/README.md)，保留模式、实际 SHA/run_id 和历史版本边界 |
| 详细计划、协作与验收 | [计划](plan-v1.0.md)、[实际审查](review-v1.0.md)、[实际验收](validation-v1.0.md) |
| 部署和演示 | [安装说明](deployment-v1.0.md)、[两部门现场场景及返工/上传](demo-v1.0.md) |
| Git 开发过程 | 每版独立 PR、检查、合并与标签；以远端实际记录为准，不编造人类贡献 |

文件是否生成、检查是否通过及发布是否完成以本版验收记录和真实仓库为准。开发计划中的交付物清单不是完成证明。自动 outputs/ 内含每次运行产物，不全部提交；仓库只纳入精选模拟证据。

## 提交前由本人确认

1. 在报告封面填写真实姓名、学号、班级、课程及教师信息；未提供部分保留填写栏，不能凭 GitHub 用户名推断。
2. 与老师确认单人加 AI 辅助开发能否满足本次安排，或补齐老师认可的人类组队要求。当前真实贡献说明保持“一名开发者 + 三个 AI 辅助角色”。
3. 重新执行八场景离线验收，保存实际索引；报告核对数据口径，明确 66.7% 是样例项目完成率。
4. 使用真实网页截图，核对截图的版本、run_id 与索引。mock 和历史真实 DeepSeek 运行分别标识，不把本次外部请求 0 写成新增真实模型验收。
5. 检查 Word 的中文、目录、表格、截图及分页。修改 Markdown 后可按安装文档重建 Word，并重新打开检查。
6. 按课程平台要求上传报告及仓库链接/压缩包。上传与教师验收没有在代码开发过程中自动执行。

若参考指导书另外列出扩展项，优先依据老师最新补充及实际评分安排确认；本版核心范围没有承诺公网部署、账号、Docker、PDF 业务报告导出、演示视频或答辩 PPT。需要额外材料时应新增真实工作和证据，不把尚未实现的内容列为已完成。

## 内容与隐私核对

提交源码不得包含 `.env`、真实 API 密钥、原始服务响应或个人上传材料。模拟数据和精选离线证据可公开；使用自有数据生成的报告、来源摘要和审计可能包含业务内容，提交前应自行核对。仓库中的模拟材料、历史真实接入用量和最终交付版的离线检查各有对应证据，不以计划、截断日志或截图标题代替实测结果。
