# v2.0-alpha.5 开发与验收计划

2026-10-17。以实验指导书及说明书R2为准，保持正常8520入口。alpha.4已通过PR #13、双CI并合并标记版本；本阶段补齐合格文档交付，不替代alpha.6/正式版的真实场景与课程报告验收。

## 分工与顺序

| 责任 | 实施范围 | 核验依据 |
|---|---|---|
| 后端/交付Agent | 不可变修订、程序内容门禁、Checker→Manager复审任务、自动完成回调、双格式artifact及恢复 | 临时DB测试，持久账本、版本/空间/哈希、拒绝与取消 |
| 前端Agent | 合格报告阅读、修订历史、正文修改、复审、MD/PDF下载和错误恢复 | TypeScript构建、客户端测试、实际浏览器 |
| 独立验收Agent | 普通两场景、真实本地PDF、复审次数及不覆盖用户文本、损坏恢复、越权与过期 | 独立黑盒断言，不依赖实现自己的哈希函数 |
| 主协调者 | API/状态集成、PDF中文字体及表格分页、依赖锁、最终审查、发布 | 完整回归、PDF逐页渲染、CI→PR合并→tag |

1. 自动验收合格后冻结事实、来源、需求和正文，生成同内容Markdown/PDF；导出失败不撤销已合格内容。
2. 人工修改只接正文叙述与建议，不能修改权威数值/来源。新增needs_review修订，旧文件保留并明确非当前。
3. 复审只调用Checker与Manager并沿用原模式，有独立幂等与两次/512输出预算上限，不重新执行前三角色/Writer，不静默改人工文字。
4. 文件绑定不可变快照哈希；每次下载核验审核凭据、快照和文件。损坏显式重导出，无模型调用；历史版本可下载但带非当前标识。
5. PDF从冻结Markdown解析，不另写报告文本。嵌入OFL中文字体，A4页眉/页脚、跨页表头、长文字安全换行；无系统字体/Word/网络依赖。
6. 合并前运行Ruff/格式、完整Python与前端测试、正常入口浏览器修改/复审/下载、中文PDF视觉验收；真实供应商两场景验证按后续整体受限预算执行。

## 退出条件

两普通场景五角色合格结果自动获得.md与.pdf；内容同源、中文与表格可读；修改必须重审、旧内容不覆盖；取消/版本/空间/快照与artifact损坏门禁通过；失败恢复和下载不产生额外付费调用。开发与测试如实标记AI辅助，不伪造三个人类贡献。
