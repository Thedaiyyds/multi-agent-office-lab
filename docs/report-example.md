# 一个可直接提交的工作汇报案例

打开正常工作台 **http://127.0.0.1:8520**。尚未启动时，在项目根目录运行：

```bash
bash scripts/start_workbench.sh
```

## 最快跑一遍：技术部季度汇报

1. 点击“新建报告”。
2. 勾选 **“使用系统本地样例数据（虚构）”**。第一次无材料时也可直接勾选；已有其他材料时先点“取消全部选择”，避免混用旧小案例。
3. 在“执行模式”选择“离线模拟（不调用模型）”，免费检查完整流程；已配置模型并要展示实际大模型时选择“真实模型协作”。
4. 把下面这段话粘贴到“汇报需求”，点击 **“开始协作”**。

> 生成2026年第二季度技术部工作汇报，包含项目进度、人员考勤、成果统计、问题与后续计划。请根据已授权的材料生成Markdown，并导出PDF。考勤只能说明所提供的样本，不得推断整个季度；不要编造其他事实。

在当前正常工作台完成即可。系统本地样例来自仓库data/office-cases的季度合成办公数据（对应TXT背景也一同冻结），是Data获得数据的一种固定接口；仅输入一句需求不能授权系统随意读取电脑文件，因此需要上面的明确勾选。

运行详情会依次显示：

**Manager需求拆解 → Planner内容规划 → Data数据整理 → Writer报告撰写 → Checker审核校验 → Manager最终验收。**

Checker发现问题时会将意见回传Writer，最多返工两次。未通过时显示实际原因；只有验收合格的内容会自动形成报告修订及Markdown/PDF文件。

## 给老师展示什么

按下列顺序讲解，通常几分钟即可展示完整过程：

1. **输入**：“我提交了技术部第二季度汇报需求，并明确授权固定本地数据接口；这些是虚构样例。”
2. **协作**：打开“节点输入输出”和“协作时间线”，展示五种角色实际接收上一步结果。最后再次调用Manager进行验收，仍是五种角色。
3. **数据**：核对项目12个、完成6个、完成率50%、成果42项。项目有36条月末快照。考勤为24人、65个虚构企业工作日、1560个人日，计划12480小时、原始实际12190.5小时、计入11899.5小时、超计划291小时、请假478小时；样本有效工时比率95.35%。接口未声明人员×日期清单，因此整体出勤率与覆盖率仍未定义，不能称为真实部门全季度出勤率。可展开统计来源查看材料、版本、行号与哈希。
4. **报告**：在“报告与文件”阅读正文，点击“Markdown 下载”和“PDF 下载”，打开实际文件，展示标题、章节、数值表、来源与中文排版。
5. **修改与复审**：点击“修改文字”，在后续计划追加一句“建议持续核对材料来源并完善业务记录。”，保存。新修订先显示待审核，点击“重新审核与验收”，展示仅Checker→Manager复审后再提供新文件。
6. **历史**：在修订选择框回到旧合格版，看到历史提示；侧栏“报告归档”可找到当前合格报告。刷新或重启后仍可查看，不会重复调用模型。

使用离线模式时，明确说明：“五角色调度、数据计算、审核与文件导出实际运行；角色语言回复使用离线夹具。”真实模式成功记录才可说明已接入实际大模型，不能混淆两者。

保存编辑时只能改变叙述与建议。需要写数字时保留已有`[[fact:F001]]`等引用，由程序渲染权威数值；直接编写新数字或改动统计事实会被拒绝。演示普通文字修改即可。

## 想展示TXT、CSV、DOCX材料接入

固定接口适合最快跑一遍。要展示指导书要求的文件读取，可先到“材料库”逐份“导入材料”，使用普通文件：

| 文件（相对仓库根目录） | 分类 |
| --- | --- |
| data/office-cases/technical-q2/项目进度.csv | 项目进度 |
| data/office-cases/technical-q2/人员考勤.csv | 人员考勤 |
| data/office-cases/technical-q2/成果统计.csv | 成果统计 |
| data/office-cases/technical-q2/工作说明.txt | 文字说明 |
| data/demo/technical-q2/季度工作记录.docx（可选旧小样例） | 文字说明 |

确认列映射，部门填“技术部”，开始日期2026-04-01，结束日期2026-07-01（不含）。CSV通常自动建议字段映射；TXT/DOCX文字说明需要明确部门与覆盖期间。预览DOCX段落和表格来源后“确认入库”。

然后新建报告，仅勾选本次四份季度材料（可选DOCX另行决定）、取消系统本地样例接口，提交同一段需求。这里选择的是普通材料；上传、执行、编辑都不修改源码或样例原件。每次运行保留自己的任务与修订记录。

## 第二个场景：行政服务满意度

新建报告，取消技术部材料，勾选“使用系统本地样例数据（虚构）”，提交：

> 生成2026年第一季度行政部工作汇报，重点突出行政服务满意度，说明样本数量、量表与数据限制。请生成Markdown，并提供PDF下载。没有往期数据时不要编造同比或提升结论。

应核对：1—5分量表216份反馈，其中12份明确无效、204份有效，分值总和810，平均约3.9706分。反馈覆盖各月及不同服务类别。不能把均分直接换算成满意率，也没有依据声称“比上季度提升”。

文件方式使用data/office-cases/administration-q1/下的满意度.csv（满意度分类）、服务说明.txt（文字说明）；若需额外展示DOCX，可上传原data/demo/administration-q1/服务记录.docx；部门行政部，期间2026-01-01至2026-04-01（不含）。

## 运行没有成功时

- 缺年份、部门或期间：按Manager提示补全需求。
- 缺材料：检查是否勾选已确认材料或固定本地样例接口。
- 真实模型报错、截断或预算耗尽：查看停在哪个角色，保留失败记录；不要把旧合格文件说成本次成功，也不要反复点击提交。
- 文件生成失败：合格修订可“生成 / 重试文件”，不会再次调用模型。
- 刷新后回看：从“报告任务”的协作记录或“报告归档”进入原报告，不必重新提交需求。

## 新旧案例与证据

本页默认使用v2.1.0的较大季度案例；原data/demo小案例、旧报告及真实模型证据原样保留，不会被改写。新大案例已做离线完整图与实际Markdown/PDF验证，离线结果不能称为新案例的真实模型验收。确定性生成算法、业务关联及精确手算见[data/office-cases说明](../data/office-cases/README.md)。新增/查看案例、读取材料和下载文件不会自动调用模型；只有提交真实协作才会消耗模型额度。
