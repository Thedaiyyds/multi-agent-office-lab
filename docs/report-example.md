# 工作汇报完整案例与演示步骤

用户需要一套普通材料和一条完整流程，能演示输入需求、五角色分工、数据整理、报告撰写、审核和输出。案例通过系统的正常入口运行，无需独立演示空间、专门端口或另建一套系统；首页不放实验案例。案例文件保持只读，运行生成独立任务记录，不改代码、密钥或已有任务。

## 当前能运行的链路

新版8520的v2.0-alpha.2目前只能保存草稿与导入材料，尚未接入五角色和报告导出。下面命令使用仓库已有的v1五角色链路，验证调度、数据工具、审核和Markdown导出；不冒充新版全流程或PDF交付。离线模型回复由夹具提供，真实LangGraph调度、数据统计和程序审核仍会运行。

在终端执行：

```bash
cd /Users/dai/Agent_SoftwareArc
uv run --locked office-agents run --mode mock --request '生成研发部2026年第二季度工作报告。日期范围为2026-04-01（含）至2026-07-01（不含）；章节依次为工作概况、主要成果、问题与风险、后续计划。'
```

输入材料直接使用仓库已有的data/samples/projects.csv、achievements.csv、issues.txt，不需复制、修改或导入数据库。命令末尾打印outputs/<本次run_id>，每次运行独立目录；这是普通任务输出，不是业务演示空间。

按下面顺序说明和核对：

1. 展示需求中的部门、季度和章节。打开projects.csv，说明同一项目存在多个日期快照，统计按本季度最新快照去重。
2. 运行命令，查看manager、planner、data、writer、checker各自passed及最终status: completed。说明五种角色依次接收上一步结果，当前模型回复为离线模拟。
3. 打开本次输出目录的nodes/，可依次查看各角色的实际输入输出；无需用动画代替运行记录。
4. 打开report.md，核对项目3个、完成2个、完成率约66.7%、成果2项。2/3是项目完成率，不是开发完成度。
5. 查看报告末尾来源文件哈希、采用的行号，以及revisions/下本轮审核结果。目录中的events.jsonl和run.json保留实际调度与状态。

## 新版最终给老师看的案例

保留一套技术部2026年第二季度案例，普通文件在data/demo/technical-q2/，目录名只是样例文件目录，不要求切换业务空间。输入需求为：

> 生成2026年第二季度技术部工作汇报，包含项目进度、人员考勤、成果统计、问题与后续计划。请根据提供的材料生成Markdown，并导出PDF。

在正常8520工作台使用材料库上传项目进度.csv、人员考勤.csv、成果统计.csv及TXT/DOCX说明，确认部门技术部、范围2026-04-01至2026-07-01（不含结束日）。后续完整实现后，在同一工作台输入上方需求并执行，展示Manager拆解→Planner规划→Data统计→Writer撰写→Checker审核/修正→Manager验收→Markdown/PDF下载。

验收应核对4个去重项目、2个完成、完成率50%、3项成果；考勤仅覆盖案例中的4个人日，计划32小时、实际28小时、请假4小时，不能宣称代表完整季度。还需实际打开最终PDF验证中文与表格。上述指标目前是材料手算预期，不是alpha.2已计算的结果。

版本按原顺序推进：alpha.3实现统计，alpha.4接入五角色和异常修正，alpha.5补齐审核及Markdown/PDF；完整新版案例须届时实际跑通后才能标记通过。测试使用临时数据，不覆盖案例原件或正常任务，不为演示增加另一套业务流程。
