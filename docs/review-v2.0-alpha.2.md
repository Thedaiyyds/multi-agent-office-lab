## 功能基线核对

| 指导书要求 | 本版落实或后续边界 |
|---|---|
| 本地TXT、CSV、DOCX | 本版材料解析、预览、来源位置、确认入库与原件下载 |
| 简单数据接口 | 本地只读模拟接口，记录冻结后可按同一流程确认；不接受外部URL |

| Markdown/PDF报告输出 | 后续报告阶段交付，本版DOCX是输入材料而非报告输出 |

## 独立案例与演示检查

- 技术案例：4个虚构项目、5条项目快照、4个模拟排班人日、3条成果、TXT和DOCX文字材料。
- 行政案例：4份虚构反馈，统一1—5分量表、TXT和DOCX服务说明。
- 不含真实姓名、学号、客户、密钥或企业数据；考勤明确不是完整季度样本。
- 统计手算只记录在案例README并标注供alpha.3参考，alpha.2界面不声称产生统计结果。
- 正常端口8520与演示端口8530分别使用outputs/workbench与outputs/demo目录；空间标记再次隔离正常/演示数据。
- 演示指南提供启动、显式加载、文件预览、接口导入、重复加载、错误提示、返回正常空间与本阶段边界；明确版本递增按同文件名/分类识别，重复加载仅对已确认材料去重，暂存草稿/原件仍保留。

## 交叉审查发现及处理

1. **进度单位不明确**：统一为0—100百分数，案例与README已修正；完成为100。
2. **可选字段可能被漏映射**：提出completed_date、leave_hours等不能只留原件而不映射；后端已增加可选字段自动建议，前端已提供显示与调整；独立演示测试确认关键列被保存。
3. **正常数据库目录容易写错**：按create_app实际默认路径修正为outputs/workbench/workbench.sqlite3。
4. **DOCX文字材料数量限制遗漏**：后端已补正文与表格行合计条数上限，新增回归测试通过。
5. **批量加载确认前未完全校验**：已补全部材料的只读全量预检后再确认。独立测试先复现“第三份CSV日期无效导致前两份部分确认”，修复后通过：无效案例确认材料数为0，修正文件后可完整加载5份。
