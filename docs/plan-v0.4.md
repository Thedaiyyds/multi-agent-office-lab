# v0.4 详细开发计划

基线：v0.3.0，main `3d50b52283d431690387393d42c127ffa4d19bc5`。目标：一条自然语言需求真正经过 Manager → Planner → Data → Writer → Checker；每步使用上一节点实际结果，审核通过才输出最终报告。版本分支 `feature/v0.4-workflow`，完成后 PR、CI、评审、合并、标签 `v0.4.0`。

## 运行约定

- `office-agents run --request '生成研发部2026年第二季度工作报告' --data-dir data/samples --mode mock` 为离线编排；`--mode live --profile deepseek` 明确调用配置的真实模型。
- 运行目录 `outputs/<run_id>/`，目录存在就拒绝覆盖。保存实际节点输入输出、模型/工具事件；不保存密钥、原始响应、推理内容或错误响应体。输入文本和校验后的本地数据是业务材料，用户上传内容默认仅留本地；提交证据只使用仓库模拟数据。
- 需求不足 → needs_input；数据无匹配或非法 → needs_input；模型/工具执行失败 → failed；审核拒绝 → review_failed；只有 completed 且审核通过才能生成 report.md。
- 本版 revision_count 固定 0，不执行自动修改。v0.5 才增加有限返工。
- 正常链路最多 6 次模型请求（Data 2 次，其余各 1 次），总输出预留上限 1984 tokens，零重试，DeepSeek thinking disabled。离线测试不消耗 API token。实测失败先离线排查，不自动重复收费请求。
- 事件至少含 run_id、UTC 时间、角色、类型、状态、节点实际耗时和安全摘要。模型/工具事件记录真实调用，节点耗时覆盖该角色执行；不把节点耗时冒充单次 HTTP 耗时。

## 验收矩阵

1. 研发部 Q2：项目 3、完成 2、完成率 2/3、成果 2；全部五节点、一次实际本地工具执行、完整审核通过报告。
2. 市场部 Q2 / 研发部 Q1：需求、大纲 ID 和对应统计值真实传递，不能复用 Q2 固定输入。
3. 缺部门/日期：Manager 终止，下游零调用，保留补充问题。
4. 无匹配 / 缺文件 / 校验异常：Data 终止，保留数据问题，不生成报告。
5. 错指标 / 缺章节：Checker 程序校验不能被模型 passed 覆盖，保留标记审核未通过的草稿。
6. 超时 / 非法 JSON / 工具异常 / 请求预算不足：明确失败，已执行节点保留，后续不调用。
7. 两次运行目录隔离，重复 run_id 拒绝；审核前草稿不能作为 report.md；导出层再次验证本地事实。
8. 干净克隆仅 uv sync --locked 即可执行离线全流程，不依赖未提交文件或 .env。

实际实现和测试结果另记 validation-v0.4.md、review-v0.4.md。运行截图要求仍需实际屏幕截图；JSON/终端记录不冒充截图。AI A/B/C 是协助角色，Git 保持真实开发者身份。
