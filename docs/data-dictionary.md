# v0.2 数据字典与模拟样例

`data/samples/` 是课程实验的人工模拟数据，不包含真实人员或客户信息，来源声明为 `simulated`。三个文件均采用 UTF-8；CSV 必须有表头和精确字段集合。详细工具行为见 [数据契约](data-contract.md)。

## projects.csv

一条记录表示某项目在某日的快照，业务键为 `project_id + snapshot_date`。同一项目允许多个日期，部门必须固定。

| 字段 | 说明 | 校验和样例 |
| --- | --- | --- |
| project_id | 项目稳定编号 | 非空字符串，如 P001 |
| department | 所属部门 | 非空，首尾空白去除，按完整文本匹配，如 研发部 |
| snapshot_date | 快照日期 | 严格 YYYY-MM-DD，如 2026-04-15 |
| status | 快照状态 | planned、active、completed、blocked 四选一 |
| progress | 当前进度百分数 | 有限数值 0～100，completed 时必须为 100 |

`planned` 表示计划中，`active` 表示执行中，`completed` 表示完成，`blocked` 表示受阻。完成数只认 `completed`，不从进度推导状态。项目在不同季度可能重复出现，但同一统计区间内只计最新快照一次。

模拟文件有 8 条数据记录、6 个唯一项目。P001 在 Q1 和 Q2 共三条快照，其中 Q2 两条，统计 Q2 时选 2026-06-20 的完成快照。P006 的快照为 2026-07-01，不属于 Q2。

## achievements.csv

一条记录表示一项成果，业务键为整个文件中的 `achievement_id`。

| 字段 | 说明 | 校验和样例 |
| --- | --- | --- |
| achievement_id | 成果稳定编号 | 非空，全文件唯一，如 A001 |
| department | 成果所属部门 | 非空、部门精确匹配，如 研发部 |
| date | 成果日期 | 严格 YYYY-MM-DD，如 2026-04-01 |
| type | 成果类型 | 非空字符串，如 功能交付、技术文档；v0.2 不设枚举 |
| description | 成果说明 | 非空字符串；合法 CSV 引号可包裹逗号或多行文本 |

模拟文件有 5 条成果记录。A001 的 2026-04-01 属于 Q2 开始边界；A005 的 2026-07-01 属于 Q3，Q2 排除。相同编号且内容相同的重复记录警告并去重；内容冲突阻止统计。

## issues.txt

UTF-8 的非结构化文本材料，模拟内容涵盖研发部、市场部和跨季度事项，没有用于程序筛选的部门/日期字段。保存原文和 `scope=unfiltered`，不会计算问题数，不能用于声称“研发部 Q2 有多少问题”。空文本允许并警告，缺文件或乱码报错。

研发部 Q2 的所选项目快照是 P001（projects.csv 第 3 行）、P002（第 4 行）、P003（第 5 行）；完成数引用第 3、4 行。成果是 A001/A002（achievements.csv 第 2、3 行）。Q1 项目引用第 6、7 行，成果引用第 4 行；市场部 Q2 项目引用第 8 行，成果引用第 5 行。这些行号含表头，来源 hash 可将引用绑定到实际文件字节。
