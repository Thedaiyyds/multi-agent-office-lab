# v2.0-alpha.2 演示指南

更正：本页记录alpha.2发布时的材料功能检查步骤，独立空间方案是开发者对“不影响开发”的误解，并非用户要求。它不能作为给老师看的完整汇报演示。后续按[完整案例操作说明](report-example.md)准备普通案例，使用正常工作台，不需要启动8530或切换空间。以下保留为历史检查记录。

## 演示目标与边界

本版可以展示“将本地文件和简单本地接口的数据接入材料库”，包含TXT、CSV、DOCX解析、内容预览、分类与字段映射、确认入库、去重、版本记录和空间隔离。

**五个Agent自动协作、项目/考勤/成果统计、审核返工、Markdown/PDF生成仍属于后续版本。** 不要把本次材料演示介绍成已经自动生成报告；可以说明它正在准备Data Agent后续需要的数据。

所有示例是虚构记录。页面不会自动填入课程案例；只有显式进入演示空间并加载案例时才出现示例材料。

## 启动

在终端执行：

```bash
cd /Users/dai/Agent_SoftwareArc
bash scripts/start_demo.sh
```

启动后打开[隔离演示工作台](http://127.0.0.1:8530/)。终端需要保持运行，按`Ctrl+C`停止。

| 用途 | 地址 | 数据库 |
|---|---|---|
| 正常开发及使用 | http://127.0.0.1:8520/ | outputs/workbench/workbench.sqlite3 |
| 本次演示 | http://127.0.0.1:8530/ | outputs/demo/workbench.sqlite3 |

端口与数据目录分别独立；演示服务内部仍区分正常/演示空间。第一次安装依赖和构建需要网络及一些时间，启动脚本本身不调用模型。不要修改`.env`，也不需要填写额外模型参数。

## 推荐演示顺序（约5分钟）

1. 打开8530，在正常空间查看首页和材料库，说明“系统默认是干净工作台，不自动导入实验案例”。如果正常空间已有你手工创建的数据，应按实际情况介绍，不能声称必定为空。
2. 进入“帮助与演示”，阅读本版能力边界，进入演示空间。
3. 切换空间会回到首页，再次打开“帮助与演示”，点击“加载演示材料”。加载后自动打开材料库，应出现项目进度、人员考勤、成果统计、工作说明和季度工作记录五份材料。若先前已导入其他材料，总数会大于5。
4. 打开项目CSV预览：讲清5行是快照记录，不等于5个项目；同一项目允许有不同日期快照。查看分类、字段映射与材料版本。
5. 打开TXT或DOCX预览：展示中文段落和DOCX普通表格已被解析。说明DOCX在这里是输入材料，报告输出要求仍为Markdown/PDF，后续接入。
6. 再次加载同一案例：观察已有材料被复用，列表数量不应重复增加。
7. 点击“导入材料”，分类选择“服务满意度”，点击“从模拟接口导入”，查看字段映射和4条反馈，再“确认入库”。第一次操作会增加一份来源为“模拟接口”的材料。介绍“这里只调用项目内的简单数据接口，不联网拉取企业数据”。
8. 返回正常空间：演示材料不可见。刷新页面再返回演示空间，材料仍在，说明数据保存与空间隔离有效。

可照着说：

> 这是材料接入阶段的独立演示。正常首页保留真实业务入口，案例只在演示空间手动加载。技术部案例包含项目快照、少量模拟考勤、成果和两种文字材料。系统负责解析、校验、字段映射与持久保存；后续Data Agent将使用这些已确认的数据。现在没有调用付费模型，也没有生成最终报告。

## 手动导入：展示TXT、CSV、DOCX三种格式

可从以下目录选择文件：

```text
/Users/dai/Agent_SoftwareArc/data/demo/technical-q2/
```

- `项目进度.csv`→项目；`人员考勤.csv`→考勤；`成果统计.csv`→成果。
- `工作说明.txt`与`季度工作记录.docx`→文字材料。
- 若设置部门与范围，技术部范围为2026-04-01至2026-07-01，采用结束日期不包含的半开区间。
- 上传后先查看预览、解析问题和字段映射，再确认入库。示例表头已按标准字段命名。
- 文件内容、分类、映射以及部门/日期范围都相同时，重复确认会复用已有版本。演示手动上传去重时，部门填“技术部”，日期填2026-04-01与2026-07-01，与批量加载设置一致；出现“确认材料版本”对话框后再确认。需要演示新版本时，将CSV复制到临时目录，**保持文件名与材料分类不变**，只修改副本内容后再上传确认；系统按同空间、同文件名和分类自动递增版本，无需单独关联入口。案例原件保持不变。

第二个备选场景在`data/demo/administration-q1/`，可手动导入`满意度.csv`、`服务说明.txt`、`服务记录.docx`；分值均为1—5。本版仅展示材料，不显示均分统计。不存在上期对照，不能声称满意度提升。

## 错误提示示范

无需改动源码或案例原件：在系统临时目录创建一个内容为`这是纯文本，不是真实Word文件`、扩展名为`.docx`的文件，上传后观察解析错误，正常材料仍可继续使用。也可以上传不支持的`.xlsx`文件观察格式提示。

不要用真实隐私文件、密钥文件或大文件测试。错误演示成功的标准是页面明确说明无法导入，不出现假成功、不污染已确认材料。

## 演示不影响开发的约束

- 演示专用端口8530，正常工作台8520仍可独立运行。
- 数据只写入`outputs/demo/`；该目录在Git忽略范围内，不会提交运行状态。
- 示例源文件只读使用，不修改代码、测试、密钥与正常数据库。
- 演示使用显式的demo空间；正常空间禁止读取演示接口。
- 本版演示无需调用模型；若页面出现后续版本的模型执行入口，不作为本次演示操作。
- 重演优先复用已有案例，重复加载不会增加已确认材料的重复版本；解析时产生的导入草稿和暂存原件仍会保留在`outputs/demo/`。不要在服务运行时手工删除或替换SQLite文件。

## 常见问题

**网页打不开**：确认终端脚本仍运行，地址端口是8530；若提示端口占用，先找到旧演示终端按Ctrl+C，再重启。不要结束不认识的进程。

**没有示例材料**：确认进入了演示空间，并完成显式加载。正常空间不显示这些材料是预期行为。

**文件找不到**：从上面的绝对目录选择；DOCX在仓库中提供，维护者可使用`data/demo/build_docx.py`重建。

**想演示完整自动报告**：alpha.2尚不能完成。后续版本接入五角色链路、统计与Markdown/PDF后，另补完整演示脚本和真实运行截图。
